# AI Service CI and Test Strategy

## Goal 13E scope

Goal 13E hardens the existing generation/review/revision system without changing the Gemini model, prompt, corpus, embedding, retrieval ranking, or official-bank rules. GitHub is the repository host and no prior `.github/workflows` convention existed, so GitHub Actions is the single CI provider.

## Job matrix

| Job | Required checks |
|---|---|
| `static` | diff whitespace, Python compileall, backend compile, frontend TypeScript/build, scoped AI frontend lint, tracked-file secret scan |
| `unit` | AI unit plus deterministic contract, Spring `Ai*`/HTTP client tests, frontend Vitest; no Gemini |
| `mysql-integration` | Testcontainers MySQL 8.4.6, all 37 Flyway migrations, schema assertions, receipt/revision repository and rollback semantics |
| `compose-e2e` | four containers, deterministic provider, auth, count 1/3, receipt, four-eyes, five original and five revision HTTP races, SQL invariants, repeat twice and cleanup |
| real Gemini | protected manual `workflow_dispatch`, non-fork only, secret required, count-one smoke |
| History RAG package | protected manual artifact download, fixed checksum preflight, package reader test |

The repository has unrelated ESLint baseline failures, so Goal 13E uses scoped lint for the AI quiz/candidate pages, services, and types. TypeScript and the complete production build remain full-project gates.

## Deterministic provider

`AI_DETERMINISTIC_E2E_PROVIDER=true` is accepted only with `APP_ENV=test` or `APP_ENV=e2e`; settings reject startup in every other environment. It is disabled by default and Compose sets it explicitly. The provider uses a tiny code-owned metadata fixture, strict JSON parsing, the production validator, Spring gateway, receipt persistence, frontend proxy, and protected provenance/search endpoints. It does not mount or modify production corpus, embeddings, or Chroma and never requires a Gemini key.

The real-Gemini workflow is manual and protected, never runs on pull requests/forks, requires the environment secret, runs only count-one smoke, and does not print generated responses. Main CI cannot depend on quota.

## Testcontainers Windows policy

Reproduction: Docker Desktop 4.61.0, Engine 29.2.1/API 1.53 (minimum 1.44), Testcontainers/MySQL module 1.21.3, docker-java npipe transport; `DOCKER_HOST` and `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE` were unset. Docker CLI worked, but default `NpipeSocketClientProviderStrategy` negotiation returned sanitized HTTP 400 at `npipe:////./pipe/docker_engine` with Desktop label `npipe://\\.\pipe\docker_cli`.

The evidence-based local fix is:

```powershell
cd backend
.\mvnw.cmd '-Dapi.version=1.44' '-Dtest=AiMySqlMigrationIntegrationTest' test
```

It connected, started Ryuk/MySQL, applied all 37 migrations, and passed without a dependency upgrade. CI Linux remains authoritative and runs Testcontainers. Docker CLI/Compose is the local fallback; a skip is reported as a skip, never a pass.

## History RAG artifact policy

`data/history-rag/v1` is a runtime import package generated by `scripts/history-rag/export_workbook.py` from an external audited semantic-active workbook. It is not a small fixture and the workbook is absent here, so policy C (external required artifact) applies; synthetic data is forbidden. `preflight_package.py` requires the fixed workbook SHA `001751243f659c449c6622ff7b417ad74fc12cf2f72dcf59305fad11bca6ee4c`, package SHA `25fea8369332b6585cab9d81ca60e9dbae6b6ffcd7cc350600a6e4878246a529`, and every manifest file checksum. The manual workflow downloads an approved `history-rag-v1` artifact by run ID, validates it, then runs `HistoryRagPackageReaderTest`.

The exporter uses stable sorting, canonical UTF-8/LF NDJSON, no timestamp in package identity, schema/package version, and ordered file hashes. Existing exporter tests cover canonical encoding and deterministic identity. The current checkout intentionally reports the missing external artifact as a blocker.

## Rollback, concurrency, and reports

`AiCandidateRepository.OfficialOptionWriter` is an injectable test collaborator, not an endpoint or environment backdoor. H2 fixtures insert the official row, option A and B, then fault; original and revision prove no official/options/chain, `APPROVED` candidate, unchanged official ID, and unchanged revision head/open candidate. A service test verifies the separate failure audit receives only `AI_CANDIDATE_PUBLISH_FAILED`, never raw exception detail.

The Compose runner sends two real HTTP publish requests through the frontend proxy behind a barrier. Each run uses five fresh original fixtures and five fresh revision fixtures, accepts only success plus defined conflict/existing-reference behavior, and asserts `1 official : 4 options : 1 chain row : PUBLISHED` in MySQL. This covers the revalidation/winner-commit race.

```powershell
.\scripts\e2e\run-ai-e2e.ps1 -Repeat 2
```

```sh
./scripts/e2e/run-ai-e2e.sh --repeat 2
```

The runner creates temporary secrets outside Git, builds, waits for health, seeds identities/target, runs the workflow, writes sanitized JSON/Markdown under ignored `artifacts/e2e/`, and always executes `down -v --remove-orphans`. Reports include aggregate latency (sample, average, P50, P95, min, max, errors) for registration/login, count 1/3 generation, save, submit, approve, source search, remap, original publish, revision create, and revision publish. These are deterministic local/CI values, not production benchmarks.

## Security and limitations

Only sanitized JUnit and E2E summaries are retained for seven days. No env, key, token, password, full response/context/chunk, vector, or production Chroma storage is uploaded. The frontend bundle contains no internal FastAPI URL/token. GitHub-hosted results become observable after review/push; local evidence is recorded now. The canonical History RAG package remains an explicit external-provisioning blocker.
