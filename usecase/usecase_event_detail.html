CHƯƠNG 3. ĐẶC TẢ USECASE XEM CHI TIẾT SỰ KIỆN

1. Use Case Specification: Xem chi tiết sự kiện lịch sử (UC-02)

Use Case Name Use Case ID Date Created Created By
Xem chi tiết sự kiện lịch sử UC-02 16/05/2026 Võ Hoàng Phúc
Primary Actors Secondary Actors
Người dùng (Độc giả/Học sinh) Hệ thống Cloudinary, External API (FPT.AI / ElevenLabs)

3.1. Brief Description
Usecase này cho phép người dùng xem thông tin chi tiết về một sự kiện lịch sử đã chọn, bao gồm diễn biến, ý nghĩa, dữ kiện chính, tư liệu hình ảnh, video (được phân chia thành các Tab) và hỗ trợ tính năng Text-to-Speech (Nghe đọc văn bản).

3.2. Pre-conditions
1. Người dùng đã chọn một sự kiện trên Timeline và Popup (EventPopup.tsx) ở bên phải màn hình đã được mở ra.
2. Hệ thống đang hoạt động bình thường với kết nối ổn định đến MySQL và Cloudinary.

3.3. Trigger
Người dùng nhấn nút "Xem chi tiết" trên Popup (EventPopup.tsx).

3.4. Post-conditions
1. Hệ thống chuyển hướng người dùng sang một trang mới (EventDetailPage).
2. Hiển thị đầy đủ thông tin chi tiết, hình ảnh, video của sự kiện đó.
3. Có thể phát âm thanh mô tả sự kiện (tính năng Text-to-Speech).

3.5. Normal Flow: Xem chi tiết sự kiện và Media (2.1)
2.1.1: EventPopup.tsx: Người dùng nhấn nút "Xem chi tiết".
2.1.2: EventPopup.tsx: Gọi lệnh Navigate chuyển hướng sang trang EventDetailPage.tsx.
2.1.3: EventDetailPage.tsx: Gọi API GET /api/events/{eventId}/detail đến EventController.java.
2.1.4: EventController.java: Gọi EventReadService.java (hàm getEventDetail).
2.1.5: EventReadService.java: Truy vấn chi tiết sự kiện, danh sách URL ảnh và URL video tại MySQL.
2.1.6: MySQL: Trả về Event Entity và các relation (Media) cho EventReadService.java.
2.1.7: EventReadService.java: Chuyển đổi thành DTO và trả về cho EventController.java.
2.1.8: EventController.java: Trả HTTP status 200 kèm DTO cho EventDetailPage.tsx.
2.1.9: EventDetailPage.tsx: Nhận dữ liệu chi tiết sự kiện.
2.1.10: EventDetailPage.tsx: Fetch ảnh trực tiếp từ URL Cloudinary.
2.1.11: Cloudinary: Trả về file ảnh tối ưu hóa.
2.1.12: EventDetailPage.tsx: Tự động Render các Section (Tổng quan, Nội dung SGK, Dữ kiện chính, Địa điểm, Sự kiện liên quan, Tư liệu Media, Nguồn tham khảo). Tại Section Tư liệu Media, hiển thị 2 Tab (Hình ảnh / Video).

3.6. Alternative Flows (Luồng Phụ)
3.6.1. Nghe đọc văn bản - Text-to-Speech (2.2)
2.2.1: EventDetailPage.tsx: Người dùng nhấn nút "Nghe đọc".
2.2.2: EventDetailPage.tsx: Gọi API GET /api/events/{eventId}/audio đến EventController.java.
2.2.3: EventController.java: Gọi EventReadService.java.
2.2.4: EventReadService.java: Kiểm tra cache file Audio trong Database.
(Trường hợp chưa có Cache trong DB)
2.2.5: EventReadService.java: Gửi Text nội dung sự kiện lên API của bên thứ 3 (FPT.AI / ElevenLabs).
2.2.6: External API: Trả về file âm thanh (MP3/WAV).
2.2.7: EventReadService.java: Upload file âm thanh lên hệ thống Cloudinary.
2.2.8: Cloudinary: Trả về URL của Audio.
2.2.9: EventReadService.java: Lưu URL của Audio vào Database để dùng cho các lần sau (Cache).
(Tiếp tục luồng chung)
2.2.10: EventReadService.java: Trả về URL Audio cho EventController.java.
2.2.11: EventController.java: Trả HTTP status 200 kèm URL cho EventDetailPage.tsx.
2.2.12: EventDetailPage.tsx: Truyền URL vào trình phát Audio Player.
2.2.13: EventDetailPage.tsx: Trình phát Audio tự động phát âm thanh.

3.7. Exceptions
- Nếu sự kiện không tồn tại hoặc xảy ra lỗi mạng khi lấy dữ liệu, EventDetailPage.tsx sẽ hiển thị trạng thái lỗi (NotFoundEventState) kèm theo danh sách các sự kiện gợi ý khác.
- Nếu dịch vụ TTS (FPT.AI/ElevenLabs) bị lỗi, tính năng "Nghe đọc" sẽ không khả dụng nhưng không ảnh hưởng đến việc xem các nội dung khác của bài viết.

3.8. Includes
- Giao diện EventDetailPage.tsx, EventPopup.tsx.
- API Spring Boot (EventController, EventReadService).
- Dịch vụ lưu trữ Cloudinary.
- External TTS API.

3.9. Assumptions
- Thiết bị người dùng có kết nối mạng internet đủ mạnh để tải hình ảnh và video.
- Trình duyệt hỗ trợ phát âm thanh HTML5 Audio.

3.10. Giải thích cơ chế truy vấn CSDL (Database Query)
Nhằm tối ưu hóa hiệu năng, hệ thống không sử dụng JPA Entity mặc định mà dùng NamedParameterJdbcTemplate để thực thi SQL thuần (Native SQL). Khi tải trang chi tiết sự kiện, EventReadRepository thực hiện tuần tự 5 truy vấn độc lập (1 truy vấn chính + 4 truy vấn con) sau đây:

1. Truy vấn chính – Lấy chi tiết sự kiện (API: GET /api/events/{idOrSlug}/detail)
- Cấu trúc Query:
SELECT e.id, e.slug, e.title, e.short_title, e.event_level, e.event_type, e.event_subtype,
e.start_year, e.end_year, e.effective_end_year, e.display_date, e.date_precision,
e.geo_type, e.lat, e.lng, e.province_names, e.historical_locations,
e.parent_id, e.root_id, e.level, e.order_in_parent, e.card_summary, e.canonical_summary,
e.detailed_narrative, e.significance, e.show_on_homepage, e.show_on_timeline, e.featured, e.status, e.raw_json
FROM historical_events e
WHERE e.status = 'published' AND (e.id = :idOrSlug OR e.slug = :idOrSlug)
LIMIT 1
- Giải thích: Khác với truy vấn danh sách (UC-01) chỉ lấy các trường nhỏ để tối ưu băng thông, truy vấn này lấy toàn bộ các trường bao gồm cả detailed_narrative (nội dung SGK dài), significance (ý nghĩa lịch sử) và raw_json (dữ liệu nguồn gốc). Điều kiện OR e.slug = :idOrSlug cho phép Client truy cập theo URL thân thiện (ví dụ: /events/chien-dich-dien-bien-phu-1954).

2. Truy vấn con – Lấy danh sách lớp học (Grades)
- Cấu trúc Query:
SELECT grade FROM event_grades WHERE event_id = :eventId ORDER BY grade
- Giải thích: Query riêng biệt để lấy mảng lớp học (10, 11, 12) gắn với sự kiện. Kết quả được dùng để hiển thị nhãn lớp và lọc nguồn SGK tương ứng trong phần Nguồn SGK.

3. Truy vấn con – Lấy danh sách tham chiếu SGK (Textbook Refs)
- Cấu trúc Query:
SELECT id, grade, book, theme, lesson, page_start, page_end, excerpt, source_key
FROM event_textbook_refs WHERE event_id = :eventId ORDER BY grade ASC, page_start ASC, id ASC
- Giải thích: Lấy các tham chiếu sách giáo khoa cụ thể (tên sách, chủ đề, bài học, số trang, trích dẫn) để hiển thị trong Section Nguồn sách giáo khoa.

4. Truy vấn con – Lấy tư liệu hình ảnh và video (Media)
- Cấu trúc Query:
SELECT id, media_type, url, caption, alt_text, source_name, license, storage_type, is_thumbnail, sort_order
FROM event_media WHERE event_id = :eventId AND status = 'active'
ORDER BY is_thumbnail DESC, sort_order ASC, id ASC
- Giải thích: Lấy danh sách tư liệu đa phương tiện. Thứ tự sắp xếp is_thumbnail DESC đảm bảo ảnh thumbnail luôn được trả về đầu tiên. Trường media_type phân biệt giữa image, video, audio, document để Frontend chia vào đúng Tab (Hình ảnh / Video). Trường storage_type phân biệt giữa URL Cloudinary và URL YouTube nhúng iframe.

5. Truy vấn con – Lấy các sự kiện liên quan (Relations)
- Cấu trúc Query:
SELECT r.relation_type, e.id, e.slug, e.title, ..., (SELECT COUNT(*) ...) AS child_count
FROM event_relations r JOIN historical_events e ON e.id = r.target_event_id
WHERE r.source_event_id = :eventId AND e.status = 'published'
ORDER BY r.relation_type ASC, r.sort_order ASC, e.start_year ASC
- Giải thích: Lấy các sự kiện có quan hệ (cause – nguyên nhân, result – kết quả, related – liên quan) để hiển thị trong Section Sự kiện liên quan. Trường relation_type giúp Frontend nhóm và gán nhãn cho từng mối quan hệ.
